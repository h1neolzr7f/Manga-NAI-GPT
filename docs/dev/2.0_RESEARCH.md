# Manga-NAI-GPT 2.0 · 研究调研与取舍（2026-10-11）

目标：做市面工具缺的东西，但**只在 CPU（8 核、可用内存约 5 GB）上能跑的才在本地实现**；需要 GPU 的方法只留可插拔后端的接口桩（stub）。
生成仍走用户自己的服务（NovelAI / OpenAI 兼容图像服务），本地负责「理解页面、管理一致性、可回退编辑、排版」。

评分：**价值**（新手痛点、市面缺口）× **可行性**（CPU、无训练、可测量）。★ = 本阶段实现。

## 本阶段实现顺序与验收

1. **角色库 2.0（#1）**：从页面框选或自动检测建立角色 → 存 CCIP 向量 + 主色 + 标签；新页面导入后自动认人（显示名字）；每格一致性分数；生成时自动带参考（NovelAI V4.5 Precise Reference / GPT 参考图 + 锚点文字）。**度量**：本仓测试页上认人准确率、每页耗时、误认（不同角色被认成同一人）次数。
2. **非破坏 AI 图层（#2）**：节点数据结构、项目保存/载入、重新生成、对比、回退；笔刷蒙版修图。**度量**：保存/载入往返一致；重算请求参数与原请求一致；回退后像素与原图一致。
3. **阅读顺序 + 自动气泡（#3）**：**度量**：已标注测试页上格序 / 气泡顺序与人工一致的比例；自动摆放的气泡与人脸重叠面积（目标 0）、离说话人距离、越格次数。
4. **剧本 → 一页（#4）**：**度量**：样例剧本（中 / 日 / 英各几段）拆分正确的格数 / 台词归属比例。
5. 有时间再做 **网点（#5）**。

GPU 类方法（#7–#9）统一放在 `js/ai/backends/` 的可选后端注册表里：接口、能力声明和「未配置」提示，不含实现。

## 诚实说明

- 「一致性分数」衡量的是**像不像库里的这个角色**（CCIP 距离），不是画得好不好；CCIP 对同一角色换装、极端角度会给出偏大的距离。
- NovelAI Precise Reference 仅 V4.5 模型可用，且与 Vibe Transfer 互斥；免费额度（Opus）下只用作少量验证。
- 本地不会训练任何模型。

## 结果：#1 角色库（2026-10-11，CPU）

做法：参考图 → 最大的脸 → 头肩框 → CCIP 特征 + 主色；页面上每张脸与角色库比较（CCIP 差异 ≤ 0.178 = 认出，≤ 0.20 = “可能是”，从不自动套用），同一格里一个角色最多出现一次。

测试集：自制 4 页漫画（`page-1..4`，1654 px 宽），人工标注 24 张脸：小美（女）、阿明（男，有时戴眼镜）、2 只猫。

| 设置 | 认对 | 认错 | “可能是”且对 | 未认出 | 猫被当成人 | 每页耗时 |
|---|---|---|---|---|---|---|
| 每人 1 张参考（第 1 页） | 20 / 22 | **0** | 1 | 1 | 0 / 2 | 1.1–1.2 s |
| 每人 2 张参考 | 19 / 20（参考脸不计） | **0** | 0 | 1 | 0 / 2 | 1.3 s |
| 消融：去掉“同一格只出现一次”规则 | 20 / 22 | **1** | 1 | 0 | 0 / 2 | 1.1 s |

- 唯一没认出的是第 2 页一张半遮挡的戴眼镜特写：它离“小美”最近（0.067），同一格规则拦下了这次错认。
- 猫与人的差异在 0.203–0.245，所以“可能是”的门槛定在 0.20（原为 0.24）。
- 浏览器真实流程（`CHARLIB_REAL=1 scripts/character-library-e2e.cjs`）：空库第 1 页找到 9 张脸（6.8 s，含首次加载模型）；点两次“加入角色库”起名后认出 7 / 9；换到第 2 页无需点击，自动认出 5 / 5（6.1 s），每格一致性 89 / 81 / 53。截图：`/workspace/shots-20261011/v2/charlib/`。
- GPT 改图：选区盖住已认出角色的脸时，自动带上该角色的参考图与外观锚点，并在状态里提示（可关）。
- 未做：自动注入 NovelAI 角色参考（Precise Reference 会消耗 Anlas，超出“只用 Opus 免费额度”的约束），已留作可选项。

## 结果：#2 AI 填充 · 非破坏图层（2026-10-11）

- 入口：任务栏「AI 填充」。笔刷 / 橡皮 / 框选 / 智能点选（SAM 2.1）涂出区域 → 一句话 → GPT 并发 3 张候选，或本机 LaMa 1 张（只去掉，免费）→ 点一张「用这张」。首次完成一次填充：**6 次操作**。
- 只在蒙版内合成：裁切 = 蒙版外框 + 60% 上下文；蒙版作为第二张参考图发给模型；返回图只取蒙版（外扩 + 羽化）部分，并用蒙版外一圈像素做整体色调校正（模型把整块重画、整体偏色时也不会出现色块）。实测图层 82% 像素完全透明，边缘为渐变。
- 图层记住：引擎、提示词、模型、裁切框、蒙版、原图裁切、全部候选、当前选择。选中图层时出现浮条：‹ › 换候选、重新生成（带着原蒙版和提示词，替换同一图层）、看原图（隐藏对比）、还原（删除图层，可撤销）。随项目保存 / 打开保留。
- 测试：核心函数单测；浏览器流程（模拟 GPT + LaMa，CI 运行）：涂抹 → 3 候选 → 应用 → 透明度检查 → 换候选 / 对比 / 重新生成 → 项目存取 → LaMa → 撤销 → 空蒙版提示 → Esc。另用真实 LaMa 在第 4 页跑通（3.1 秒）。
- 未做：真实 GPT 三候选（本轮未调用中转）；跨分镜框的蒙版不会自动保护边框（与 GPT 改图的边框保护尚未接入）。

## 结果：PSD 导入 / 导出（ag-psd 31.0.3，MIT）（2026-10-11）

- 导出：文件菜单「导出当前页为 PSD（保留图层）」。每个画布对象一层（名称、显示/隐藏、不透明度、混合模式）；文字 → 可编辑文字层（竖排标记 vertical）；AI 填充层 → 不透明候选图 + 图层蒙版（羽化边在蒙版里，PS / Krita / Photopea 里可继续改）。
- 导入：「导入漫画页」直接接受 .psd（文件菜单也有「导入 PSD」）。底层（铺满画布时）成为页面，其余图层逐个放上；组展开；蒙版合进透明度；混合模式与不透明度映射；隐藏层保持隐藏；文字层 → 可编辑文本框。当前页已有内容时，PSD 自动放到新的一页。
- ag-psd 830 KB，第一次用 PSD 时才加载（启动不变慢）。
- 顺手修了一个导入 bug：长宽都 ≤ 400 像素的图片被当成“毫米”，页面变成 3150×2362 且图片缩在角落；超过 4096 的大图页面被缩小但图片没缩。现在按像素等比缩放，图片正好铺满页面（400×300 → 683×512，5000×7000 → 2926×4096）。
- 测试（CI）：导出 → Node 端解析结构（图层数、文字、隐藏、蒙版内外、AI 层不透明）→ 再导入；另造一个“第三方” PSD（组、蒙版、正片叠底 50%、隐藏、偏移）导入后逐项核对，包括像素级的蒙版合成。

## 结果：命令层 + 历史面板（PhotoCraft 思路）（2026-10-11）

- 命令注册表 `Commands.register/run`：任务向导、文件、设置、图层编辑共 21 条命令（选中对象时才出现「复制 / 删除 / 翻转 / 置顶 / 置底」）。

- 缩略图 96 px，在保存时同步生成（几毫秒），只保留最近 60 步的缩略图。
- 测试：16 条标签单元测试 + E2E（CI）。

## 结果：#3 阅读顺序 + 自动放对白气泡（2026-10-11）

思路：Kurlander 等 Comic Chat（SIGGRAPH 1996）的气泡规则（靠近说话人、按阅读顺序、不挡脸），Chun 等 2006 自动气泡布局的代价搜索，Magi（arXiv:2401.10224）的日漫阅读顺序。全部 CPU、无需新模型。

- 分格阅读顺序：先分行（上→下），行内再分列（日漫右→左，列内上→下），所以右侧通栏高格会先于左边上下两格。可切换为左→右。
- 每个气泡在格内做网格搜索，代价 = 挡脸（重罚）+ 画面细节（梯度 + 墨量）+ 与已有气泡 / 文字 / 页面上原有字的重叠（重罚）+ 阅读进度位置 + 格内顺序一致 + 离说话人远近；尾巴指向说话人，在脸框外 6 px 停住（射线与脸框求交）。
- 人脸：新接口 `/manga-smart/faces`（只跑人脸检测器，约 0.2 s，按页缓存，从不弹下载；没装人物识别组件时只避开画面细节）。页面原有文字：直接用导入时 改字幕 已读好的每页缓存。
- 画一页漫画：对白可用 / 分成多句（每格最多 4 个气泡），整页画完后统一排；命令面板「自动排对白气泡」可随时重排（保留用户改过的文字和颜色，一步撤销）；「显示阅读顺序」叠加编号。
- 实测（4 张真实狗粮页，27 张脸、18 处原有文字、14 格，每格 1–2 句）：

| 指标 | 旧规则（固定右上角） | 新布局 |
|---|---|---|
| 挡住的脸 | 5 | **0** |
| 盖住原有文字（px²） | 770,234 | **0** |
| 阅读顺序错误 | 2 | **0** |
| 气泡互相重叠 | 0 | 0 |
